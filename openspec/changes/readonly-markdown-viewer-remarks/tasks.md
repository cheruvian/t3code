## Decisions (scope resolutions made during implementation)

- **Rendered-view checkbox toggling (`setMarkdownTaskChecked`) is not wired into the new viewer.** Before this change, `ChatMarkdown`'s rendered view let a reader toggle a task-list checkbox, which wrote back into the raw file source via `setMarkdownTaskChecked`. The `markdown-file-preview` spec's "Read-only rendering" requirement explicitly forbids content changes through the rendered view ("no changes are made to the underlying file content"), and `@t3tools/remarks-renderer`'s `Markdown` component has no equivalent callback. Per the parent guardrail, `setMarkdownTaskChecked` itself (and `isMarkdownPreviewFile`) are left completely untouched in `filePreviewMode.ts` and remain tested — they're simply no longer called from `RenderedMarkdownSurface`. Raw-source editing (where checkboxes are just text) is unaffected, since that path (`EditableFileSurface`) was not touched.
- **`LocalCommentAnnotation` was not literally "replaced" for markdown files** because it was never used in the rendered markdown view to begin with — `RenderedMarkdownSurface` previously rendered `ChatMarkdown` with no commenting affordance at all. `LocalCommentAnnotation` is used only inside `EditableFileSurface`, the line-based raw/code-editor comment surface shared by every file type via `@pierre/diffs` (markdown's raw view included). Per the design's non-goals ("raw source editing, if any, is out of scope") and the `markdown-file-preview` spec (non-markdown/raw behavior unaffected), `EditableFileSurface`/`LocalCommentAnnotation` were left untouched; the new `@t3tools/remarks-annotations`-based anchored commenting is additive, scoped entirely to the new read-only rendered view.
- **Vendored two extra packages beyond the five named in the proposal**: `@remarks/store` and `@remarks/diff` are transitive dependencies of `@remarks/annotations` (via `ReviewedUnit`'s changed-section comparison view) and were vendored as `@t3tools/remarks-store` / `@t3tools/remarks-diff` for the vendored `@t3tools/remarks-annotations` to build and function correctly, consistent with the design's intent to compose anchor + store + review + renderer + diff.
- **Fixed a pre-existing bug in the vendored source**: `packages/remarks-annotations/src/styles.css` had a stray trailing `}` (present in the upstream `~/workplace/remarks` source too) that broke Tailwind's CSS parser when the stylesheet was imported into `apps/web`. Removed the extra brace; this is a copy-time fix, not a t3code-specific customization.
